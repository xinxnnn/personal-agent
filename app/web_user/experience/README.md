# 信锚 Agent-Anchor：独立个人用户前端

保留原用户端、TP/AP 管理端和原 Python 业务代码，新增本目录静态资源与独立运行管理模块。

启动项目原有三个 bat 后访问：

http://127.0.0.1:8110/user/static/experience/login.html

独立登录页验证账号密码后进入工作台。直接访问工作台时会检查服务端会话，未登录则跳转登录页；退出登录后返回登录页。

前端无需构建步骤或外部 CDN。使用已有用户端账号登录。OpenClaw 实例运行仍要求主机具有 Node.js/npm 和 Git。

## 已接入

- 用户登录、会话检查、退出。
- 最近一次智能体绑定记录、身份凭证展示。
- 上传照片、提交审核、手动查询审核状态，包括拒绝处理。
- 从 AP 加载能力矩阵、选择能力、签发绑定凭证、生成文件与启动指引。
- OpenClaw 环境检测、TP/AP 地址设置。
- 网页保存实例模型配置、后台安装依赖、启动、查询进度、停止与打开对话页面。
- 「系统更新」复用原工作台接口：Octopus 可重新选择并提交 PA 能力配置，OpenClaw 可查看与更新已安装 Skill。更新前需停止对应主实例，更新后重新启动。

## 演示步骤

日常使用可进入导航「我的伙伴」：左侧选择主智能体或子智能体，右侧启动、停止、打开对话或修改模型连接。切换仅改变管理对象，不会停止其他实例。手机端伙伴列表显示在操作区上方；点击「创建子智能体」会在当前页面打开独立创建窗口。

1. 登录新工作台，进入创建智能体，填写与登记信息一致的身份信息和照片。
2. 提交申请，在原 TP 管理端完成审核，回到新前端查询结果。
3. 选择类型并加载能力，确认绑定，生成智能体。
4. 在「让伙伴开始工作」中确认模型地址、名称和 API Key，点击「部署并启动」。无需运行生成的 bat。
5. 服务就绪后点击「开始对话」。首次安装可能需要数分钟，实际对话使用实例的原生界面。

## 启用网页部署

更新后管理员需重启 `start_user_8110.bat` 一次；入口已切换为 `app.experience_app:app`，复用原用户端并注册独立运行接口。TP/AP 不需要修改。用户只通过网页操作。

运行接口仅接受本机已登录会话，拒绝跨站请求。安装使用固定命令参数，不执行用户输入的路径或命令。每个实例使用独立端口；不会停止全局 Gateway。安装失败或启动失败会在网页提示，可重试。模型密钥写入本地实例 `.env`，不回显。

正常关闭用户服务会停止它管理的实例和本机 ANP 网关；服务被强制终止时，Windows 可能留下子进程，管理员需处理。刷新页面可以恢复当前用户服务进程内的任务状态；重启服务后重新启动实例。Octopus 网页启动会自动准备本机 ANP 网关，并为实例连接独立的接收器。

## 运行健康巡检

用户服务启动时自动启用 `app/runtime_watchdog.py`，每 15 秒检查本服务已成功启动的实例。OpenClaw 同时检查进程存活和 `/readyz` 的就绪状态；Octopus 检查进程和页面响应。巡检不调用模型接口。

连续 3 次失败后进入「自动恢复中」，按约 10、20、40 秒退避等待，最多自动重启 3 次（实际等待受巡检间隔影响）。连续健康运行 10 分钟后重置重启额度。达到上限后停止自动重试，在网页提示人工检查。首次部署失败需手动重试，自动恢复不会重新安装组件或修改模型配置。

主动停止或已删除的实例不会自动拉起。更新后重启 `start_user_8110.bat` 并刷新网页即可生效。巡检只在用户服务运行期间有效，不能恢复用户服务本身或整机故障；模型连接是否可用仍以实际对话为准。

## 子智能体

OpenClaw 或 Octopus 主智能体生成后，在「我的伙伴」点击「＋ 创建子智能体」，填写名称、分工并选择对应类型支持的能力。Octopus 支持文本处理、新闻搜索、网页浏览和网页对话；不显示 OpenClaw 的 shell 等选项。提交成功后自动进入新伙伴的运行管理，继续部署与启动；失败时保留填写内容并显示原因。工作台的「我的子智能体」也提供同一创建窗口入口。点击伙伴列表中的主智能体可切回主实例。

复用 `SubAgentConfig`、原 `create_sub_agent` 和 `local_store/agent_groups` 分组格式。原创建逻辑仅调整了独立目录编号和追加分组成员，避免同名覆盖、列表只剩最后一个的问题。兼容接口补充运行清单，并将主实例模型连接复制到子实例，密钥不发送到浏览器。子实例状态从运行管理读取，不使用旧接口仅修改的 `running` 标记。

子智能体继承主身份关联，不表示另获 TP 签发身份。Octopus 子实例从项目模板构建，独立保存模型连接、能力清单和运行环境，沿用现有分组及删除审批；旧子实例若缺少运行清单会提示管理员迁移，不擅自改写历史数据。

## Octopus 主子通信协同

在「我的伙伴」中分别启动主、子 Octopus 实例，并从各自对话页选择同组在线伙伴进入 ANP 通信。目标智能体会使用自身模型生成回复。用户工作台在运行管理面板下方显示「智能体通信协同 · 工作日志」，按时间记录智能体启动/停止、协同请求发出/收到、结果返回/接收和失败事件；不展示消息正文或问答内容。

通信实际经过仓库 `anp-proxy` 的 HTTP → ANPX/WebSocket → ReceiverClient；组内身份认证通过后，由目标 Octopus 的聊天模型处理请求并返回回复。网关仅监听 127.0.0.1，接收器只开放组内消息路径；本机组成员使用每次启动生成的独立令牌校验，令牌不返回浏览器。网关和路由文件由用户服务管理，`local_store/anp_groups` 含本地认证信息，不应对外发布。

工作日志从组事件库和各成员的本地会话库汇总事件元数据，因而可以补显示实例尚未重启前已经产生的协同会话。日志只返回参与智能体、同组伙伴、事件类别、发生时间、会话编号和处理状态，不保存或展示问答内容。日志按时间刷新，不显示统计卡片。公网 DID-WBA 身份解析和跨组通信不在此功能范围内。

## OpenClaw ANP 消息收发

OpenClaw 主、子实例同样使用「主子伙伴通信」。本机 Python 适配器与 Node 网关由同一个运行进程树管理，随实例启动、停止和归档删除。适配器仅接收消息，不向 OpenClaw 模型会话提交任务。

两个系统的收发记录均保存在实例根目录的 `anp_messages.sqlite3`，重启后保留。工作台仅显示去内容化的通信事件，不显示消息正文或问答记录。

更新后重启 User 服务并重新启动主、子实例，刷新网页。若创建 Octopus 子智能体仍提示需要 OpenClaw，说明旧 User 服务尚未退出；当前创建接口依据主实例实际运行包选择构建器，Octopus 无需安装 OpenClaw。

## 边界

## 删除审批

主智能体在工作台「删除申请」中提交；子智能体在卡片上点击「申请删除」。填写原因后进入待审核状态，TP 页面底部「智能体删除审批」可批准或拒绝。批准后用户刷新审批结果，点击「执行已批准的删除」。更新后需重启 User 和 TP 服务。

主智能体有子智能体时拒绝删除，需先处理子智能体。旧直接删除接口已关闭。执行前检查审批状态和实例清单，停止本服务管理的进程，目录移至 `local_store/deleted_agents/<申请编号>`，同步移除分组中的子记录及匹配的最近创建记录。原凭证签发记录保留。这是归档删除，不是永久擦除；归档目前由管理员维护。

审批记录保存在本机共享 SQLite，重启后保留；适用于本项目 User/TP 同机部署。远程部署需额外接入可信审批服务，不能直接共享本地审批文件。

该版本展示真实接口状态，不模拟对话、在线状态或审核成功。技能维护、恢复等高级操作继续通过原控制台完成。服务页面就绪不等于模型密钥验证成功，模型调用需以实际回复为准。

使用后端现有的全局最近一次快照，不提供多租户隔离。后端目前采用演示账号、固定测试密钥和本地部署模式；新前端并不将其改造为可公开运营的多用户服务。

不在浏览器存储身份证、照片、凭证、密钥或密码；连接地址保存在 localStorage，审核编号保存在按账号区分的 sessionStorage。绑定完成但尚未生成期间刷新页面，需要重新加载能力并绑定。
